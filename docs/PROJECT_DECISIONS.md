# Kliper.City: журнал решений

Этот файл фиксирует решения, чтобы разные чаты не спорили с уже принятым направлением.

## Принятые решения

| Дата | Решение | Почему | Последствие |
|---|---|---|---|
| 2026-07-06 | Проект делится на доменные чаты, а не только на страницы | Фильтры, stories, карточки и mobile пересекают страницы | Введен `CHAT_OWNERSHIP.md` |
| 2026-07-06 | `js/app.js` считается legacy/generated и не редактируется для обычных UI-правок | Основной риск сломать каркас SPA | Правки делаются через CSS, data и отдельные JS-модули |
| 2026-07-06 | Motion подключен как локальная global-библиотека | Проект без корневой сборки, CDN не нужен | Использовать `window.KLIPER_MOTION` |
| 2026-07-06 | v1 сначала стабилизируется, v2 не смешивается с текущей работой | Иначе социальные/CRM-функции начнут ломать витрину | Использовать `V1_V2_ROADMAP.md` |
| 2026-07-06 | `Топ` переносится в v2 | Подтверждено владельцем | В v1 держать скрытым/не развивать |
| 2026-07-06 | `Мой двор` переносится в v2 | Подтверждено владельцем | В v1 держать скрытым/не развивать |
| 2026-07-06 | `Районы` переносятся в v2 | Подтверждено владельцем | В v1 использовать только как вспомогательные данные, если нужно |
| 2026-07-06 | `Кабинет компании` входит в v1 | Подтверждено владельцем | Создать отдельный рабочий поток и v1-страницу/раздел |
| 2026-07-06 | Форма заявки не делается сейчас | Владелец хочет доработать вопрос отдельно | Не добавлять форму без отдельной задачи |
| 2026-07-06 | Backend и авторизация нужны в конце v1 | Подтверждено владельцем | Планировать auth для пользователей и застройщиков после стабилизации UI |
| 2026-07-06 | Социальные функции должны быть полноценными | Подтверждено владельцем | Реализовывать через backend/auth, не считать localStorage финальным решением |
| 2026-07-06 | Stories scroll-правило подтверждено | Подтверждено владельцем | Раскрытие stories колесом делать позже в Stories & Motion |
| 2026-07-07 | Ролевые профили, теги любимого и рецензии-рекомендации оформляются как будущая продуктовая модель | Подтверждено в Product / UX Lab | Вынесено в `ROLE_PROFILES_SCOPE.md`; v1 не перегружать реализацией ролевых тарифов, stories и публикаций обычных пользователей |
| 2026-07-08 | Role profiles не добавляются в текущий v1 UI | Подтверждено владельцем | Держать как future-state: финал v1 после backend/auth или v2; не выдавать UI/backend задачи без отдельного implementation brief |
| 2026-07-08 | CTA ролевого профиля: `Стать автором или специалистом` | Подтверждено владельцем | Использовать как approved copy для future-state личного профиля |
| 2026-07-08 | Тариф физлица: `Профиль автора`, гипотеза `990 ₽ / мес` | Подтверждено владельцем | Не показывать как реальную оплату до backend/auth/billing; использовать в future specs |
| 2026-07-08 | `Представитель компании` делится на два слоя: публичная роль физлица + доступ к кабинету через company membership | Подтверждено владельцем | Не смешивать B2C role tariff с B2B company cabinet/pricing/CRM |
| 2026-07-08 | Privacy default: личные действия приватны, публичны только агрегаты и явно опубликованные рецензии | Подтверждено владельцем | Favorite tags, likes и personal lists не раскрывать без явного выбора пользователя |
| 2026-07-08 | Favorite tags: стартуют только стандартные теги, custom tags позже после moderation | Подтверждено владельцем | Использовать стандартный набор из `ROLE_PROFILES_OWNER_QUESTIONS.md`; custom tags не проектировать как v1 UI |
| 2026-07-08 | Блок `Почему советуют`: 3 рецензии; материалы компании и партнеров отдельно от organic top | Подтверждено владельцем | Company/partner materials маркировать отдельно и не показывать как независимые рецензии |
