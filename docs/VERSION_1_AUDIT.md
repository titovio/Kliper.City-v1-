# Kliper.City v1: общий аудит

## 1. Технология и устройство проекта

Kliper.City сейчас устроен как статический SPA-сайт. Точка входа проекта - `index.html`. Основное React-приложение собрано в legacy/generated-бандл `js/app.js`. Дополнительные модули подключаются отдельными JS-файлами поверх основного приложения.

Отдельного backend в текущей версии не найдено. Данные имитируются через JS-массивы на `window.KLIPER_*`, JSON-файлы и `localStorage`.

В корне проекта нет `package.json`, поэтому обычную сборку через `npm build` запускать нельзя. Проверка JavaScript выполняется через `node --check` для отдельных файлов. Отдельные подпроекты могут иметь свои `package.json`, но они не являются основной сборкой сайта.

## 2. Основные папки и файлы

| Зона | Путь | Назначение |
|---|---|---|
| Вход | `index.html` | Подключение CSS, данных, основного приложения и дополнительных модулей |
| Legacy app | `js/app.js` | Основное React SPA: страницы, карточки, профиль, модалки, лайки, подписки |
| Данные | `js/data/` | Застройщики, ЖК, бизнес-помещения, районы, истории, фильтры, настройки |
| Каталог | `js/catalog/` | Дополнительный рендер карточек и бизнес-раздела |
| Поведение | `js/behavior/` | Навигация v1, истории, тема, восстановление страницы, профиль |
| Фильтры | `js/filters/` | Мобильные фильтры и selected tags |
| Страницы | `js/pages/` | Надстройки страниц ЖК, застройщика, топа, двора |
| Стили | `css/` | Базовые стили и полировка интерфейса |
| Архив | `_archive/` | Не подключенная в основной сайт заставка/архивные материалы |

## 3. Роутинг

Классического файлового роутинга нет. Все основные экраны находятся внутри одной страницы `/index.html`.

Переходы работают через:

- внутреннее состояние React-приложения;
- кнопки разделов;
- hash `#card=Название` для больших страниц карточек;
- дополнительные DOM-модули, которые реагируют на состояние страницы.

Это значит, что "страницы" проекта фактически являются режимами одного SPA.

## 4. Хранение состояния

Используются `localStorage` и `sessionStorage`.

| Ключ | Назначение |
|---|---|
| `kliper-liked-cards` | Локальные лайки карточек |
| `kliper-card-reviews` | Локальные рецензии пользователя |
| `kliper-subscribed-cards` | Подписки на карточки |
| `kliper-subscribed-districts` | Подписки на районы |
| `kliper-last-view` | Последний режим просмотра |
| `kliper-last-open-page` | Последняя открытая карточка/страница |
| `kliper-page-restore-active` | Служебный ключ восстановления страницы |
| `kliper-theme` | Светлая/темная тема |
| `kliper-top-card-actions` | Локальные действия страницы топа |

## 8. Главные технические риски

1. `js/app.js` является legacy/generated-бандлом, но в нем находится основной каркас.
2. Много модулей работают поверх уже отрисованного DOM и зависят от текста кнопок, `aria-label` и структуры карточек.
3. Фильтры реализованы в нескольких местах: внутри app, в каталогах, в mobile-файлах и в бизнес-полировке.
4. Застройщик и ЖК используют общий механизм большой страницы, поэтому правка одного типа может задеть другой.
5. CSS-слои могут конфликтовать, особенно в stories, фильтрах, темной теме и карточках.
6. Скрытые разделы остаются в коде и могут ломаться незаметно.
