# Kliper.City: полноценные социальные функции

Решение владельца от 2026-07-06: социальные функции должны быть полноценными.

## Что значит "локальные"

Локальные функции работают только в браузере пользователя и обычно хранятся в `localStorage`.

Примеры:

- лайк сохранился только в текущем браузере;
- подписка видна только текущему пользователю;
- рецензия не ушла на сервер;
- друзья и чаты существуют только как визуальные блоки.

Локальное состояние допустимо сейчас как прототип, но не считается финальным решением v1.

## Что значит "полноценные"

Полноценные функции работают через backend и авторизацию.

Примеры:

- у пользователя есть аккаунт;
- у застройщика есть аккаунт/кабинет;
- лайки и подписки сохраняются на сервере;
- рецензии видны другим пользователям;
- друзья, чаты и подборки связаны с реальными пользователями;
- застройщик видит подписчиков и рецензии в кабинете компании.

## Решение для v1

Backend/auth делается в самом конце v1, после стабилизации UI.

До backend/auth:

- UI можно оставлять локальным/визуальным;
- нельзя считать localStorage финальной архитектурой;
- не нужно ломать текущий прототип ради раннего backend.

В конце v1:

1. авторизация пользователя;
2. авторизация застройщика/компании;
3. серверное хранение лайков;
4. серверное хранение подписок;
5. серверное хранение рецензий;
6. связь кабинета компании с компанией;
7. базовая социальная модель.

## Вопрос на уточнение перед backend-этапом

Нужно решить, что входит в первый backend-срез:

- только аккаунт + лайки + подписки + рецензии + кабинет компании;
- или сразу также друзья, чаты и публичные подборки.
