# Kliper.City: baseline regression report

Дата проверки: 2026-07-06.

Цель: зафиксировать текущее состояние сайта как точку отсчета перед разделением работы на отдельные чаты.

## Итог

Текущая версия сайта загружается и основные v1-разделы переключаются. Критической локальной ошибки JS/CSS/Motion в проверке не найдено.

Найдены риски:

- в DOM есть скрытые/внеэкранные дубликаты навигационных пунктов;
- простые автотесты по тексту могут кликать не тот элемент;
- есть внешние ошибки загрузки Clearbit/Unsplash;
- профиль после перехода из бизнес-раздела визуально открывается, но в DOM остаются заголовки бизнес-карточек выше профиля, это требует отдельной ручной проверки видимости/слоев.

## Профиль

Профиль открывается через `button[aria-label="Моя страница"]`.

Фактические признаки:

- URL получает `#card=Мария`;
- найдены заголовки `Мария`, `Мой дом`, `Лента дома`, `Соседи рекомендуют рядом`, `Чаты`, `Друзья`;
- horizontal overflow: `0`.

Риск:

- если открыть профиль после бизнес-раздела, в списке DOM-заголовков перед профилем остаются заголовки бизнес-карточек. Нужно ручное визуальное подтверждение, видны ли они пользователю или это только скрытый/оставшийся DOM.

## Риск для будущих автотестов

Первый прогон по `getByText(...).first()` не смог кликнуть разделы, потому что находил внеэкранные/скрытые элементы из боковой/дублирующей навигации.

Правило для тестов:

- не кликать `getByText(...).first()` для навигации;
- выбирать visible button в viewport;
- использовать стабильные `data-kliper-testid` из `TEST_INFRASTRUCTURE.md`.

## Рекомендации

1. Создать отдельную задачу для Regression QA: ручная визуальная проверка профиля после перехода из каждого раздела.

3. Создать задачу для Assets/Data: заменить внешние Clearbit-логотипы локальными fallback-ассетами или убрать сетевые запросы.
4. Не чинить эти пункты в рамках документационной подготовки, чтобы не смешивать стабилизацию с функциональными изменениями.
