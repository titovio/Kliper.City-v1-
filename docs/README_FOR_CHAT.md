# Kliper.City: пакет для анализа чатом

Этот пакет нужен, чтобы быстро обучить отдельный чат фактическому состоянию проекта Kliper.City v1.

## Как использовать

1. Загрузить в чат все файлы из архива.
2. Сказать чату: "Изучи эти документы как базу знаний проекта Kliper.City. Отвечай по ним, отделяй факты от предположений, не придумывай отсутствующие функции".
3. Начинать с `PROJECT_INDEX.md`.
4. Для вопросов по продукту использовать `VERSION_1_AUDIT.md`, `SITE_MAP.md` и `PAGE_PASSPORTS.md`.
5. Для вопросов по данным использовать `DATA_STRUCTURE.md`.
6. Для вопросов по будущим правкам использовать `UI_AND_CHANGE_RULES.md`, `CHAT_OWNERSHIP.md`, `REGRESSION_CHECKLIST.md` и `TASK_BRIEF_TEMPLATE.md`.
7. Для запуска отдельного рабочего чата использовать готовый промпт из `WORKSTREAM_PROMPTS.md`.

## Важное ограничение

Документация описывает фактическое состояние текущей версии сайта по коду и визуальной проверке. Это не техническое задание на новую версию и не список обещанных функций.

Если в документации написано "частично", "визуально", "скрыто" или "не найдено", значит функция не подтверждена как полностью рабочая.

## Для рабочих чатов

Если чат должен править проект, он обязан:

1. Определить свою зону по `CHAT_OWNERSHIP.md`.
2. Заполнить задачу по `TASK_BRIEF_TEMPLATE.md`.
3. Не трогать соседние зоны без согласования.
4. Проверить результат по `REGRESSION_CHECKLIST.md`.
5. Если решение продуктовое - записать его в `PROJECT_DECISIONS.md` или `OWNER_DECISIONS_QUEUE.md`.

Если владелец проекта недоступен, чат обязан действовать по `AUTONOMY_PROTOCOL.md`.
