# Kliper.City: v1 / v2 roadmap

Цель документа - не смешивать текущий этап с будущим продуктом.

## v1: что доводим сейчас

v1 должна быть стабильной витриной продукта.

### Обязательные зоны v1

- Главная оболочка.
- Каталог застройщиков.
- Каталог новостроек.
- Каталог готовых ЖК.
- Каталог бизнес-помещений.
- Карточки.
- Быстрый просмотр карточки.
- Большая страница ЖК.
- Большая страница застройщика.
- Stories.
- Профиль пользователя.
- Лайки.
- Подписки.
- Локальные рецензии.
- Фильтры.
- Selected tags.
- Сброс фильтров.
- Light/dark theme.
- Mobile.
- Кабинет компании.
- Backend/auth в финальной части v1.
- Полноценные социальные функции через backend/auth в финальной части v1.

### Допустимые упрощения v1

- Данные могут быть локальными.
- Лайки/подписки могут храниться в `localStorage`.
- Рецензии могут быть локальными.
- Форма заявки сейчас не делается и будет доработана отдельно.
- До backend/auth социальные сценарии могут оставаться визуальными, но финальная цель v1 - полноценные функции.

## v2: не делать внутри v1 без решения

- CRM.
- Реальные заявки.
- Получение предложений от застройщиков.
- Журнал/QR.
- Полноценная карта с геоданными.
- Админка.
- API.
- Топ.
- Мой двор.
- Районы как полноценная отдельная страница.

## Отдельно: кабинет компании

Решение владельца от 2026-07-06: кабинет компании входит в v1.

Текущий статус: есть только визуальный блок на странице застройщика.

Если переносить в v1, минимальный безопасный вариант:

- отдельная страница/модалка без backend;
- dashboard с mock-данными;
- без авторизации;
- без реальной отправки заявок;
- без изменения публичной страницы застройщика.

Финальный вариант v1 после backend/auth этапа:

- вход для застройщика/компании;
- привязка кабинета к компании;
- управление публикациями/stories;
- просмотр подписчиков/рецензий/обращений;
- базовая статистика.

## Отдельно: backend, авторизация и социальные функции

Решение владельца от 2026-07-06: backend будет, авторизацию нужно сделать для пользователей и застройщиков в самом конце v1.

Также подтверждено: социальные функции должны быть полноценными, не только локальными.

Это значит:

- текущие UI-разделы сначала стабилизируются без backend;
- localStorage остается временным прототипным состоянием;
- затем проектируется auth/data model;
- затем подключается backend;
- после backend повторно проверяются профиль пользователя, кабинет компании, подписки, рецензии, друзья, чаты и публичные подборки.

## Отдельно: форма заявки

Решение владельца от 2026-07-06: без формы заявки сейчас. Этот вопрос будет доработан отдельно.

## Что сейчас считается успехом

Пользователь понимает:

1. Какие есть застройщики.
2. Какие есть новостройки/ЖК.
3. Какие есть бизнес-помещения.
4. Как быстро посмотреть контент через stories.
5. Как лайкнуть/подписаться.
6. Где его профиль.
7. Как оставить/увидеть рецензию как локальный сценарий.

Застройщик понимает:

1. Что у компании есть карточка.
2. Что объекты можно смотреть отдельно.
3. Что есть репутационный слой.
4. Что в будущем возможны подписки, рецензии и предложения.
