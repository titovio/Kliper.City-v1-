# Kliper.City: где нужен владелец проекта

Этот файл нужен, чтобы владелец мог спокойно уйти, а вопросы не блокировали техническую работу.

## Что можно делать без владельца

- Создавать документацию.
- Уточнять карту проекта.
- Писать чеклисты.
- Проверять сайт.
- Исправлять явно технические ошибки, если не меняется дизайн/сценарий.
- Приводить документацию к актуальному виду.
- Готовить предложения и варианты.

## Где владелец нужен обязательно

| Вопрос | Почему нужен владелец | Можно ли работать вокруг |
|---|---|---|
| Какой backend/auth стек выбрать | Влияет на архитектуру финального v1 | Да, отложить до backend-этапа |
| Детальный состав социальных функций | Нужно определить MVP соцслоя | Да, пока стабилизировать UI |
| Какой финальный сценарий формы заявки | Владелец решил доработать отдельно | Да, не добавлять форму сейчас |
| Какие статусы ЖК считать готовыми | Сейчас данные неоднозначны | Да, документировать риск |
| Когда можно трогать `js/app.js` | Высокий риск | Только с явным разрешением |
| Детальный формат `Кабинета компании` | Кабинет входит в v1, но нужен сценарий | Да, проектировать отдельно |

## Заготовка вопросов владельцу

1. Кабинет компании должен быть отдельной страницей, drawer или модалкой?
2. Кто входит в кабинет: застройщик, менеджер компании или админ Kliper?
3. Backend/auth стек: что выбираем для пользователей и застройщиков?
4. Соцфункции в конце v1: нужны ли сразу друзья, чаты и публичные подборки, или сначала аккаунт + лайки + подписки + рецензии?

## Если владелец спит

Работать только с тем, что не требует продуктового выбора:

- документация;
- регрессия;
- поиск рисков;
- технические проверки;
- подготовка задач для отдельных чатов;
- отчеты.
