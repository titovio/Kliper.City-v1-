# Kliper.City: протокол приемки отчетов рабочих чатов

Дата: 2026-07-06.

Этот документ описывает, как Architect / Main принимает результаты рабочих чатов и превращает их в безопасные задачи.

## Зачем это нужно

Рабочие чаты могут одновременно найти дефекты в одних и тех же файлах. Без приемки это приведет к конфликтующим правкам.

## Что считается отчетом

Отчет должен содержать:

- роль чата;
- проверенную зону;
- список дефектов P0/P1/P2;
- шаги воспроизведения;
- предполагаемые файлы;
- риск изменения;
- рекомендацию: исправлять сейчас, отложить, передать другой зоне.

## Правила приоритета

| Приоритет | Что значит | Что делаем |
|---|---|---|
| P0 | сайт зависает, раздел не открывается, критическая JS-ошибка, ломается основная навигация | разрешить точечное исправление сразу |
| P1 | заметный дефект UX/UI или логики v1, но сайт работает | поставить в ближайшую очередь |
| P2 | косметика, оптимизация, будущая плавность, не мешает v1 | отложить до стабилизации |
| V2 | функция вне текущего v1 | записать в roadmap/backlog |

## Порядок приемки первой волны

1. Принять `Regression QA`.
2. Из него выделить P0 и подтвержденные P1.
3. Принять `Assets/Data Cleanup`.
4. Разрешить только безопасные ресурсные правки без `js/app.js`.
5. Принять `Filters System`.
6. Разрешить минимальную унификацию фильтров, если она не трогает карточки и stories.
7. Принять `Visual System`.
8. Разрешить визуальные правки только после фиксации фильтров, если они касаются тех же панелей.
9. Принять `Stories & Motion`.
10. Реализацию задачи номер один запускать отдельным этапом после фильтров и базовой регрессии.

## Запрещено при приемке

- Объединять несколько доменных задач в одну большую правку.
- Давать двум чатам одновременно менять один файл.
- Разрешать редактирование `js/app.js`, если есть обходной слой.
- Исправлять P2 до закрытия P0/P1.
- Создавать вторую волну чатов до первого набора отчетов первой волны.

## Формат решения Architect / Main

Для каждой принятой задачи фиксировать:

```text
Задача:
Источник:
Приоритет:
Разрешенные файлы:
Запрещенные файлы:
Проверка после правки:
Кто делает:
```

Если задача спорная, заносить ее в `OWNER_DECISIONS_QUEUE.md`.
