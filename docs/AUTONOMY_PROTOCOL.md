# Kliper.City: автономный протокол работы

Этот документ описывает, что можно делать без владельца проекта, особенно ночью или в длинной автономной сессии.

## Главная цель автономной сессии

Улучшать управляемость и качество проекта без риска сломать визуал или бизнес-логику.

## Разрешено без владельца

- Создавать и уточнять документацию.
- Писать чеклисты и шаблоны задач.
- Проверять текущий сайт.
- Составлять списки дефектов.
- Искать конфликтующие стили/скрипты.
- Делать техническую уборку только если она не меняет внешний вид и поведение.
- Готовить патчи, но не внедрять рискованные изменения без владельца.
- Обновлять `CHANGE_LOG.md`.

## Запрещено без владельца

- Переписывать `js/app.js`.
- Менять каркас `index.html`, кроме явно безопасных подключений.
- Удалять скрытые разделы.
- Менять сценарии stories при скролле.
- Менять продуктовый состав v1.
- Внедрять новые крупные функции.
- Массово менять CSS всего сайта.
- Подключать новые зависимости через npm.

## Стоп-условия

Остановиться и записать вопрос в `OWNER_DECISIONS_QUEUE.md`, если:

1. Нужно выбрать между двумя продуктовыми сценариями.
2. Исправление требует менять несколько доменов сразу.
3. Нужно удалить код, который может использоваться.
4. Нужно менять `js/app.js`.
5. Нельзя проверить результат локально.

## Ночной порядок работы

1. Проверить `PROJECT_INDEX.md`.
2. Выбрать одну безопасную зону.
3. Сформулировать задачу через `TASK_BRIEF_TEMPLATE.md`.
4. Сделать минимальную правку или документ.
5. Проверить по `REGRESSION_CHECKLIST.md`.
6. Записать результат в `CHANGE_LOG.md`.
7. Если возник вопрос владельцу - записать в `OWNER_DECISIONS_QUEUE.md`.

## Что считать хорошим ночным результатом

- Проект стал понятнее.
- Следующие чаты могут стартовать быстрее.
- Ничего не сломано.
- Все спорные вопросы вынесены в очередь владельца.
- Есть проверяемый список дальнейших задач.
